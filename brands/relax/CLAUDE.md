- **百貨店・商業施設内へのテナント出店が多い**(たまプラーザ東急百貨店・水戸京成百貨店・
  FKDインターパーク・イオン入間・サクラス戸塚)。路面店と集客導線の前提が違う可能性がある

同じ「戸越銀座」エリアに [LUNA](../luna/CLAUDE.md) の店舗もあるが、業態(マッサージ vs
ピラティス)もドメインも別物の**完全な別ブランド**。混同しないこと。idは
`relax-togoshiginza` と `luna-togoshiginza` でブランド接頭辞が違うため衝突しない。

## 触ってはいけないもの

**調査が終わるまで、テーマのマークアップ(クラス名・DOM構造)をリファクタしないこと。**

Sprocket / Optimize Next はCSSセレクタで要素を掴んでDOMを書き換えている。構造を変えると
**実施中のA/Bテストがエラーも出さずに壊れる**(全員にコントロールが出る、または意図しない
場所に差し込まれる)。数字が動かないだけなので「この訴求は効果がなかった」と誤判定し、
テスト結果自体が汚染される。**CSSセレクタは「契約」として扱う。**

### 集客実績: 「リラックス新規客経路集計」シート

オーナーは `t-kuribayashi@keizgroup.jp`。タブ「**集客数(新ルール6月〜)**」で管理されている。

### GA4は「アカウント単位」で1回だけ権限を付ける(重要)

店舗ごとに25プロパティあるが、**プロパティごとに25回付与する必要はない**。GA4管理画面の
左「アカウント」列 →「アカウントのアクセス管理」→「+」→ サービスアカウントのメール
アドレスを追加 → 権限「閲覧者」。**この1回で配下の全プロパティが読めるようになる。**

プロパティ単位の付与(画面上はこちらのほうが目に付く)は、同種の案件で最初に選んで
間違えた選択肢。症状は **GA4 Admin API のプロパティ一覧が空の `{}` で返る**こと。
権限を付けたのに一覧が空なら、アカウント単位ではなくプロパティ単位で付いている。

付与後は Admin API の `accountSummaries` でプロパティを列挙し、**プロパティ名で店舗に
突き合わせる**。25個のプロパティIDを人が手で書き写す必要はない(写し間違いは
そのまま別店舗の数字になる)。

突き合わせは [`scripts/ga4_properties.py`](../../scripts/ga4_properties.py) が行う。
**認証情報は要らない**(入力はプロパティ名の一覧なので、ローカルセッションが報告してきた
一覧をそのまま食わせられる):

    python3 scripts/ga4_properties.py --brand リラックス --names properties.txt

1対1に定まったものだけを対応表に入れ、**同じ店舗に2つ当たった / どの店舗にも当たらない /
プロパティが見つからない店舗がある**場合は書き出さずに終了する(終了コード1)。
半端に埋まった対応表は「取り込めていない店舗」と「数字がゼロの店舗」を区別できなくする。

### Search Consoleはプロパティごとの付与しかできない

GA4のような一括付与が無いため、対象プロパティごとに「ユーザーを追加」を個別に行う
(権限は「フル」)。付与後は `sites.list` でサービスアカウントから見えるサイトを列挙できる
ので、URLの形式(`sc-domain:` かURLプレフィックスか)を人が入力する必要はない。
**リラックスは1ドメインなので、GSCがドメインプロパティ1つなら付与も1回で済む可能性がある。**
実際にいくつあるかは付与後の `sites.list` で分かる。
