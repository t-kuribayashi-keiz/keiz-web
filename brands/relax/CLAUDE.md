## 触ってはいけないもの

**調査が終わるまで、テーマのマークアップ(クラス名・DOM構造)をリファクタしないこと。**

スプロケット / Optimize Next といったA/BテストツールがCSSセレクタで要素を掴んでDOMを
書き換えている。構造を変えると**実施中のA/Bテストがエラーも出さずに壊れる**
(全員にコントロールが出る、または意図しない場所に差し込まれる)。数字が動かないだけなので
「この訴求は効果がなかった」と誤判定し、テスト結果自体が汚染される。
**セレクタは「契約」として扱う。**

詳細と調査項目は [docs/backlog.md](../../docs/backlog.md) の
「リラックス WordPress環境の実態調査」を参照。

## 分析環境(構築中)

### 方針

他ブランドで確立した型に合わせる([brands/smile/CLAUDE.md](../smile/CLAUDE.md) の
「分析基盤へのアクセス方法」と同じ):

- GCPプロジェクトは全社共通の `keizgroup-automation`(プロジェクト番号578587097928)
- **サービスアカウントはブランド単位**で分ける。リラックス用は
  `relax-reporter@keizgroup-automation.iam.gserviceaccount.com` を想定
  (鍵漏洩時の被害範囲を限定でき、ブランドとの関係が終われば削除で済む)
- 鍵ファイルはローカルPCとGitHub Secretsにのみ置き、**チャットにもリポジトリにも
  一切含めない**

### 集めるデータ(長い形式の統合ログ)

`(年月, 店舗, チャネル, 指標, 値)` の1行1レコードで貯める。ダッシュボードより先に、
**この形にそろえて結合できる状態を作るのが目的**。先行指標(順位・流入・CTR)の動きが
実績(来店・予約)の動きにどれだけ先行するか——その時間差が、施策の効果を語る根拠になる。

| ソース | 取れるもの | 取得方法 | 状態 |
|---|---|---|---|
| GA4 | セッション・チャネル別流入・店舗ページ別PV・CV(予約ボタン/電話タップ/LINE) | GA4 Data API | **プロパティ構成が未確認** |
| Search Console | 表示回数・クリック・CTR・平均掲載順位(クエリ別/ページ別) | Search Console API | **プロパティ形式が未確認** |
| 広告費シート | 店舗別の広告実額 | Sheets API(既存の共有基盤) | 読める見込み |
| HPB(SalonBoard) | 掲載枠・クーポン・予約枠 | 既存Skill(要ローカル実行環境) | 一部稼働 |
| 実績(来店・予約数) | 店舗×チャネルの集客数 | **所在が未確認** | — |
| SEO/MEO順位ツール | キーワード×店舗の順位推移 | ツール次第(APIが無ければCSVをDriveに置く運用) | **ツールの有無が未確認** |

### 埋まっていない前提(これが揃うまで実装に入らない)

1. **GA4のプロパティ構成** — 1つか、店舗ごとに25個か、そもそも入っていないか
2. **Search Consoleのプロパティ** — ドメインプロパティかURLプレフィックスか。
   GA4はアカウント単位で一括権限を付けられるが、**GSCはプロパティごとに個別付与が要る**
3. **集客実績の所在** — スマイルでいう「グッド・スマイル月次報告」に相当するシートが
   リラックスにあるか。無ければ何を実績とみなすか(HPBの予約数? POSの来店数?)
4. **順位計測ツールの有無** — GRC・MEOチェキ等。APIが無いツールならCSVをDriveに
   置いてもらう運用にする

**推測で埋めない。** それらしい数字が入ると誰も気づかないままKPIの傾向判断が狂う。
