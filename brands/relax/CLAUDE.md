## 触ってはいけないもの

**調査が終わるまで、テーマのマークアップ(クラス名・DOM構造)をリファクタしないこと。**

スプロケット / Optimize Next といったA/BテストツールがCSSセレクタで要素を掴んでDOMを
書き換えている。構造を変えると**実施中のA/Bテストがエラーも出さずに壊れる**
(全員にコントロールが出る、または意図しない場所に差し込まれる)。数字が動かないだけなので
「この訴求は効果がなかった」と誤判定し、テスト結果自体が汚染される。
**セレクタは「契約」として扱う。**

詳細と調査項目は [docs/backlog.md](../../docs/backlog.md) の
「リラックス WordPress環境の実態調査」を参照。

### GA4は「アカウント単位」で1回だけ権限を付ける(重要)

店舗ごとに25プロパティあるが、**プロパティごとに25回付与する必要はない**。GA4管理画面の
左「アカウント」列 →「アカウントのアクセス管理」→「+」→ サービスアカウントのメール
アドレスを追加 → 権限「閲覧者」。**この1回で配下の全プロパティが読めるようになる。**

プロパティ単位の付与(画面上はこちらのほうが目に付く)は、同種の案件で最初に選んで
間違えた選択肢。症状は **GA4 Admin API のプロパティ一覧が空の `{}` で返る**こと。
権限を付けたのに一覧が空なら、アカウント単位ではなくプロパティ単位で付いている。

付与後は Admin API の `accountSummaries` でプロパティを列挙し、**プロパティ名で店舗に
突き合わせる**。25個のプロパティIDを人が手で書き写す必要はない(写し間違いは
そのまま別店舗の数字になる)。

### Search Consoleはプロパティごとの付与しかできない

GA4のような一括付与が無いため、対象プロパティごとに「ユーザーを追加」を個別に行う
(権限は「フル」)。付与後は `sites.list` でサービスアカウントから見えるサイトを列挙できる
ので、URLの形式(`sc-domain:` かURLプレフィックスか)を人が入力する必要はない。
**リラックスは1ドメインなので、GSCがドメインプロパティ1つなら付与も1回で済む可能性がある。**
実際にいくつあるかは付与後の `sites.list` で分かる。
