### HPB(ホットペッパービューティ)の分析状況(2026-09-06 実物確認)

「グッド・スマイル月次報告」の月次タブ(『◯月HP(速報値)』)は、月に1タブの中へ
**HP / HPB / meta / オフライン のブロックを縦に並べる**構造。直営がチャネルごとに別タブを
持つのと違うので、タブ名だけでHPBを引くことはできない(詳細と罠は
[functions/hpb-ribbon-kpi/CLAUDE.md](../../functions/hpb-ribbon-kpi/CLAUDE.md)の
「ブランド系列(--profile)」)。

HPBブロックに**既に入っているもの**: 院別×月次のHPB集客数(当月/前月/前月比較/過去14か月の
参考値/過去3か月平均との比較)、ブログ数の前月・今月。行はスマイル13行(閉院した
はつしば院・うりわり院を含む。集計に使うのは有効11院)。

**空のまま(全店「-」)のもの**: 口コミ評点 / 口コミ件数 / 比較サロン最高点 / 予約枠(×の数) /
当月前月低評価口コミあるか。直営ではこれらがリボンデータ(店舗別PDF)と予約枠チェックから
埋まっている。**列(受け皿)は既にあり、中身が無い**というのがスマイルの現状。

埋めるのに要るのは、(1) スマイル5院ぶんのリボンPDFがHPBから届いているかの確認、
(2) `GCP_SMILE_GOOD_KEY` のSecret登録、(3) 転記先Masterの決定。いずれも未了。

### 分析基盤へのアクセス方法(重要な制約)

このクラウド実行環境からは、Googleスプレッドシートの**特定タブ(gid)を指定して開く
手段がない**(Google Drive連携ツールは常に先頭タブしか取得できず、`export?gid=...`の
直接URLもネットワーク制限でブロックされる)。CSV手動エクスポートは可能だが、継続的な
運用には非効率。

そのため、`.claude/skills/customer-acquisition-consulting/`のGA4/GSC/Sheets API
サービスアカウント連携のplaybookを、この「グッド・スマイル月次報告」シート向けに
適用することにした(2026-09-02、栗林さんと合意)。

**サービスアカウントの発行単位**: ブランド単位(法人単位)。GCPプロジェクトは全社共通で
1つ(`keizgroup-automation`)にまとめるが、サービスアカウントはブランドごとに分ける
方針とした。理由: (1) 鍵漏洩時の被害範囲を限定できる、(2) ブランドとの関係が終了した際に
そのアカウントごと削除すれば済む、(3) この組織自体が`brands/<ブランド名>/CLAUDE.md`で
ブランドごとに文脈を分ける設計になっており、認証情報の境界もそれに合わせる方が一貫する。
