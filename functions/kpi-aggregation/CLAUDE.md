## 数字の性質(重要)

同じ月の数字に**3つの段階**がある。取り違えると分析が壊れる:

| 段階 | 内容 |
|---|---|
| **中間値** | 月の途中(例: 8/16)時点の累計を日割りで逆算した**見込み**。月内の進捗把握用 |
| **速報値** | 月が終わって全データが揃った時点の数字。KPIの判断に使う |
| **確定値** | 速報値からさらに確定した数字。シート上に「速報値➤確定値で+0.3」等の補正メモがある |

**ダッシュボードに中間値が入ったまま月をまたぐと、未達に見える。** 月初に速報値へ更新する
のがこの集計作業の目的。

## 月次の更新手順(6工程)

栗林さんが毎月手作業で行っている流れ。①②⑤が自動化の対象。

| # | 内容 | 自動化 |
|---|---|---|
| ① | 「◯月HP(速報値)」「◯月HPB (速報値)」「◯月Epark(速報値)」各タブの合計集客数を「年間計画・目標」タブの該当月の行に転記。あわせてAB・AC・AE列のUU数を「◯月HP(速報値)」タブの合計から転記 | **対象** |
| ② | 同じ行のL〜O、Q〜S列に店舗数を記入(HP=速報値タブ / HPB=広告費シート / EPARK=専用シート) | **対象** |
| ③ | V・W列のPPC広告・META広告の集客数 | **保留**(現在チャットでやり取りして手入力。2026-09-02時点で自動化しない判断) |
| ④ | F列の紹介、J列のオフライン合計、X列のAIを別シートから転記 | 未着手(転記方法を別途ヒアリング) |
| ⑤ | 揃った1店舗当たりの数字(自動計算される行)を「2026年Web集客KPI管理ダッシュボード」タブのAG〜AO列へ転記。**AK列のSEO集客数は SEO+MEO+AI の合算値** | **対象** |
| ⑥ | Googleトレンドの集計 | 未着手(方法を別途ヒアリング) |

①〜④が揃うと、対象月の行から1店舗当たりの集客数が自動計算され、それをKPIとして使う。

## 実装方式: サービスアカウント + Sheets API(GitHub Actions実行)

**当初はGASを提案したが、2026-09-02に方針変更した。** 決め手は栗林さんの指摘:

> 今後あなたに全て任せる運用にしていく際は、チェックするという意味で
> あなたがスプシの実行内容を確認できるべきではないですか?

GASはスプレッドシート内部で動くため鍵も権限付与も不要で手軽だが、**Claudeが実行結果を
検証できない**。書いて終わりになり、間違っていても誰も気づかない。全面委任を目指すなら
この盲点は許容できない、と判断してサービスアカウント方式に切り替えた。

検証は「ブラウザで画面を見る」ではなく**APIでのセル単位の読み取り**で行う。画面のスクリーン
ショットから数値を目視で読むのは、桁の読み違いや見落としが起きるため検証手段として弱い。

- 実行: GitHub Actions(鍵は`GCP_KPI_WRITER_KEY`シークレット)
- **鍵はClaudeのコンテキストに入らない**。Chatwork連携と同じ設計
- 検証: スクリプト自身が「書き込み前の値・書き込んだ値・読み返した値」をログに出し、
  Claudeがそのログを機械的に照合する

サービスアカウント: `chokuei-sunsumirai-kpi-writer@keizgroup-automation.iam.gserviceaccount.com`
(既存2つと違い**書き込み権限を持つ**ため、名前でそれが分かるようにしている)

## 設計上の必須要件: 合計行を固定で書かない

栗林さんの指摘(2026-09-02):

> 8月HP(速報値)は集客数がN157、AU157、BB157、BL157です。
> **ただし店舗数が変わったりするとこの位置も変わるので、都度確認が必要です。**

**セル位置をコードに直書きしてはいけない。** 店舗が1つ増減すると合計行がずれ、
合計ではない別の行を読む。**エラーは出ないので、ズレた数字がそのままKPIになる。**

実装では毎回、合計行を動的に特定する(「合計」ラベルの検索、または最終データ行の判定)。
特定した行が本当に合計行かを検証してから値を使い、検証に失敗したら**書き込まずに止める**。

## 未確定事項(推測で書き込みコードを作らないこと)

本番の業務シートなので、セル位置を推測したまま書き込むと**気づかないうちに誤った数字が入る**。
`probe.gs`の実行結果で以下を確定させてから実装する:

1. **「8月HP(速報値)」タブの N157 / AU157 / BB157 / BL157 がそれぞれ何か** —
   HP集客数・SEO UU数・MEO UU数・PPC UU数の4つと推測されるが、どれがどれか未確定
   (※行番号は上記のとおり固定で使わない。列の位置と意味だけを使う)
2. **U列(SEO,MEO集客数)の出どころ** — 工程①〜④のどこにも現れない。⑤でAK列=SEO+MEO+AI
   とされているため、SEO・MEOの集客数がどこかに存在するはず
3. **広告費シートで直営 / サンズ / ミライ の3つをどう判別するか** — 「2026年8月の列に金額が
   入っている店舗の数」を数えるが、M/N/O列は3分割。店舗名から判別するとのことなので、
   `data/clinics.json`の`corporation`(サンズ / ミライ)と突き合わせられる可能性がある
4. **EPARKシートのB列の法人名の値** — どの値が直営 / サンズ / ミライに対応するか
5. 「年間計画・目標」タブの正式なシート名

これらはサービスアカウント(`chokuei-sunsumirai-kpi-writer`)の読み取りが通れば、
Claudeが自分で該当タブを読んで解決できる。ユーザーへの確認往復を増やさない。
