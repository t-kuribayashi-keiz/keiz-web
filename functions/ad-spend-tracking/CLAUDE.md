# 広告費管理(ブランド横断の社内機能)

このファイルは、複数ブランドが共有する「広告費」スプレッドシートによる媒体掲載広告費の
一元管理についての個別コンテキストです。ルートの [CLAUDE.md](../../CLAUDE.md) に定義
された全社共通ルールを前提とし、矛盾する場合は常にルートCLAUDE.mdを優先する。

`functions/`配下に置いているのは、これが特定の1ブランドに閉じたものではなく、
**直営・サンズミライ・グッド・スマイル・リラックスの5ブランドを横断して管理される
社内の共通基盤**であるため([functions/recruiting/CLAUDE.md](../recruiting/CLAUDE.md)、
[functions/receipt-agency/CLAUDE.md](../receipt-agency/CLAUDE.md)と同じ位置づけ)。

## データソース

- スプレッドシート名: 「広告費」
  (https://docs.google.com/spreadsheets/d/1aH6L_cMz95PbZs9plKYHBKv7G0LG5dFSuO0ON1mCmnM/)
- 所有者: ga_admin@keizgroup.jp
- 期間: 2017年1月〜2027年12月の月次列(将来分も含めて列だけは用意されている、実データは
  直近月まで)

### 使用中/不使用のタブ(2026-09-02、ユーザー確認済み)

- **使用中**: 「広告費各詳細」— これが実質的な唯一のデータソース
- **不使用(無視してよい)**: 「エキテン詳細」「年計」「Line」「Line のコピー」

このクラウド環境のタブ一括取得(gid指定不可)で読み取った際、上記の不使用タブの内容が
「広告費各詳細」の内容と地続きに混ざって見えていた(「Line」「院名」という見出しを
含む同一店舗リストが2回繰り返し出現した箇所などがそれに該当すると見られる)。今後
このシートを扱う際は、サービスアカウント経由でタブを個別指定して「広告費各詳細」
だけを読むこと。

## シート構造(2026-09-02時点で確認した内容)

1行1店舗、列が年月という「ワイド形式」の巨大な単一シート。以下のブロックに分かれている:

| ブロック | 内容 |
|---|---|
| 全社チャネル別サマリー(冒頭) | プラチナ/ゴールド/正会員(エキテンの会員ランク)、PPC各種(直営・アイワ・アテナ等)、HPB美容/直営、SNS系(レセワン)等 |
| 直営(約150院) | 院ごとの月次広告費 |
| サンズミライ | サンズ側(たいよう/あやめ/おかだ/河内いわふね)+ミライ側(弁慶はりきゅう各院/堺市美原区/和歌山駅東口) |
| スマイル | すまいる/やまもと/山本の各院(6院分の行を確認。院マスタの11院とは一致しない可能性があり要確認) |
| グッド(7院) | 姿勢堂各院+ひなた鍼灸接骨院 |
| リラックス(約30院、閉院含む) | リフレッシュセンターリラックス各店。「宇都宮東口駅前店」など閉院店舗の履歴行も残っている |
| 掲載削除セクション | 閉院・削除済み店舗の履歴(`すまいる針灸接骨院ラソラ川西院`など、[brands/smile/CLAUDE.md](../../brands/smile/CLAUDE.md)の完全除外店舗と一致確認済み) |
| 集計サマリー(複数箇所) | エキテン合計/PPC(直営院)/HPB(美容)/HPB(直営院)/アイワ/全合計 |

### 未確認・要確認事項

- スマイルブランドについて、このシートでは6院分の行しか確認できていないが、院マスタ
  (`data/clinics.json`)では11院。全院が広告費管理の対象か、一部院のみ対象かは未確認
- 「アイワ」チャネル行(集計サマリーに登場、月ごとに変動する金額)の正体は、ユーザーに
  確認したところ**追わなくてよいとのこと**(2026-09-02)。上記の「不使用タブが混ざって
  見えていた」ことが原因だった可能性が高い。今後もこの項目を深追いしない

## アクセス方法

このクラウド実行環境のGoogle Drive連携ツールには特定タブ(gid)を指定して開く手段が
なく、CSV手動エクスポートも都度作業が必要で非効率(詳細は
[brands/smile/CLAUDE.md](../../brands/smile/CLAUDE.md)の「分析基盤へのアクセス方法」
参照、同じ制約)。

**サービスアカウントの方針**: このシートは5ブランド共有のリソースのため、専用の共有
サービスアカウント `ad-spend-reporter@keizgroup-automation.iam.gserviceaccount.com`
(予定)を1つ発行し、5ブランド分をこの1アカウントでカバーする(2026-09-02、栗林さんと
合意)。GCPプロジェクトは全社共通の`keizgroup-automation`を使う([brands/smile/CLAUDE.md](../../brands/smile/CLAUDE.md)の
`smile-good-reporter`と同じプロジェクト)。鍵ファイルの取り扱いは
`.claude/skills/customer-acquisition-consulting/`の非交渉ルールに従い、このクラウド
セッションでは扱わずローカルPC側でセットアップする。
