## 調査待ち(実機・外部環境の確認が必要)

### リラックス WordPress環境の実態調査 ★次にやる

25店舗のWordPress編集をAI化するための設計を確定させたいが、推測で進めると事故るため実機確認が必要。
XServerへのSSHが要るので、**ローカルのClaude Codeセッション**で実施する。

確認事項:

1. **All in One SEO のバージョンと保存先** — v3系なら`wp_postmeta`(`_aioseo_title`等)、v4系なら専用テーブル
   `wp_aioseo_posts`。v4だと`wp post meta update`が効かないため、タイトル/ディスクリプションの
   更新方法が根本的に変わる。`wp db query "SHOW TABLES LIKE '%aioseo%'"` で判別できる
2. **25店舗のテーマ構成** — 完全に別テーマか、同名テーマの中身違いか
3. **`front-page.php`の店舗間の差分の大きさ** — 2〜3店舗を`diff`すれば傾向が掴める。
   差分が「文言だけ」なのか「構造」なのかで、親子テーマ化の設計が変わる
4. **WP本体/PHPのバージョン、WP-CLIが使えるか**
5. **スプロケット / Optimize Next のタグの埋め込み場所** — テーマ内か、タグマネージャ経由か。
   **各ツールが掴んでいるCSSセレクタも要記録**(下記のリスク参照)
6. **WP外の共通ディレクトリの実際のパスと参照方法** — どのドメインから配信し、各店舗がどう読んでいるか

**この調査前に絶対にやってはいけないこと**: テーマのマークアップ(クラス名・DOM構造)のリファクタ。
スプロケット/Optimize NextはCSSセレクタで要素を掴んでDOMを書き換えるため、構造を変えると
**実施中のA/Bテストがエラーも出さずに壊れる**(全員にコントロールが出る、または意図しない場所に
差し込まれる)。数字が動かないだけなので「この訴求は効果がなかった」と誤判定し、テスト結果自体が
汚染される。セレクタは「契約」として扱うこと。
