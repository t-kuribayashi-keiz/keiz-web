# 院名 → 店舗ID 突き合わせの落とし穴

`data/hpb-review-blog-ids.json` を新しく作った・拡張した際(2026-09-07)に実際に踏んだ
落とし穴の記録。院マスタを追加・修正するときは必ず目を通すこと。

## 1. データソースの取得方法: read_file_content では大きいスプレッドシートの一部タブが欠落する

Google Drive連携の `read_file_content`(自然言語表現)は、大きいスプレッドシートだと
**一部のタブがまるごと欠落した状態**で返ってくることがある。2026-09-07、「予約枠チェック」
用スプレッドシート(ID: `15lWYMvRjY3hGVvPu_IgmGHx4ER3joCERFDEzVd8aLrI`)で、`read_file_content`
では「AIチェック用」「AIチェック用ver.2」の2タブ(合計86店舗)しか取れなかったが、実際には
「直営」「ミライ・サンズ」「子会社」の3タブに165院中162院分のURLがあった。

**対策:** 大きいスプレッドシート全体を確実に読みたい場合は `download_file_content` で
`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet` としてXLSXをダウンロードし、
`openpyxl` でローカルに全タブを読むこと。`read_file_content` は「だいたいの内容を素早く把握する」
用途にとどめ、網羅性が必要な突き合わせ作業には使わない。

## 1.5. read_file_contentの行番号は実際のシート行番号より2大きい(Markdown変換のズレ)

`read_file_content` はスプレッドシートをMarkdownテーブルとして返すため、出力の先頭に
実際のシートには存在しない2行(空行+Markdownの区切り記法行 `| :-: | :-: | ...`)が
挿入される。そのため**「Markdown出力のN行目」は「実際のシートのN-2行目」に対応する。**
2026-09-07〜08、これに気づかずMarkdown出力の行番号をそのままGoogle SheetsのName Box
(セル参照)に使ってしまい、「書き込み位置が2行下にずれるGoogle Sheets側のバグ」と
誤診断して半日近く費やした(詳細は
[references/sheet-write-back.md](sheet-write-back.md) 参照)。

**対策:** `read_file_content` の出力から抽出した行番号を、Google Sheets APIやName Box
など「実際のシートの行番号」を要求する場所に渡す前に、必ず2を引く。もしくは最初から
`download_file_content` → `openpyxl` で読み、実際の行番号をそのまま使う(この経路では
このズレは発生しない)。

## 2. Unicode正規化(NFC/NFD)の不一致で文字列比較が静かに失敗する

同じスプレッドシートの中でも、セルによってテキストがNFC(合成済み、例: "ば" = U+3070単体)と
NFD(分解済み、例: "は" U+306F + 濁点結合文字 U+3099)の異なる正規化形式で保存されていることが
あった。見た目もコピー結果も同じ文字列に見えるが、Pythonの `"わかば" in text` のような単純な
文字列比較は**エラーも出さずに静かに失敗する**(該当箇所を素通りする)。

**対策:** 外部から取り込んだテキストは必ず `unicodedata.normalize("NFC", s)` してから
比較すること。この不一致に気づかず「該当なし」と誤判定して30分近く原因調査に費やした。

## 3. 「整骨院/接骨院/整体院」表記ゆれは、接尾辞ではなく院名の途中に埋まっていることがある

多くの院は末尾だけが違う(例: "◯◯整骨院" vs "◯◯接骨院")ので末尾のsuffixを一律で
取り除けば揃うが、一部のチェーン(例: 「弁慶はりきゅう整体院 西大津院」)は
**チェーン名の直後、院名の途中**に業態語が入っている。末尾だけをstripする実装だと
これらは別の文字列のまま残り、突き合わせに失敗する。

**対策:** 業態語(鍼灸整骨院/鍼灸接骨院/接骨院/整骨院/整体院/治療院/院)を、末尾だけでなく
**文字列中のどこにあっても**取り除いてから比較する(正規表現の `sub` で全置換)。

## 4. 最も危険な落とし穴: 同じ拠点に業態違いの別院が2つあるケース

**これが実際に5院分の誤りを生んだ根本原因。** 「本八幡南口整体院」と「本八幡南口鍼灸接骨院」の
ように、同じ拠点名で業態語だけが違う**別々の院**が両方とも口コミブログチェック表に載っている
ことがある。院マスタ側にはどちらか一方の店舗IDしか無いことが多く、業態語を取り除いて
突き合わせると**両方が同じ店舗IDに一致してしまう**。

このとき危険なのは、片方を確定させたあとにもう片方を突き合わせようとすると、「候補が1件しか
無い(もう片方は既に処理済みリストから除外されているので衝突が見えない)」ため、衝突検知が
すり抜けてしまうこと。2026-09-07はこれで5院に誤って重複した店舗IDを割り当ててしまい、
最終検証(実測値と手動集計値の突き合わせ)で初めて発覚した。**2026-09-08、この5院は
HPBジャンル検索(下記7参照)で個別に正しい店舗IDを発見して解決済み。**

**対策:**
1. 突き合わせは**その場限りの候補プールだけでなく、既に確定した全ての院との衝突**も
   毎回チェックする。
2. 業態語を取り除いた結果、**口コミブログチェック表側に同じベース名を持つ院が複数ある**
   場合は、自動突き合わせを諦めて手動確認に回す。
3. 自動突き合わせで確定させた後も、**最終的にスクレイプした実測値を手動集計値と突き合わせて
   一致するか確認する**まで信用しない。名前が一致しているように見えても、実際には隣の
   別院のデータを取得している可能性がある(HPBの店舗ページの表示タイトル自体が
   「整体院」なのに実際は「整骨院」の店舗を指している、といったラベルの不整合も観測されており、
   タイトル文字列だけでの確認も過信できない — 実測の口コミ数・★5数・ブログ数が手動集計と
   近い値になるかどうかが最終的な判断材料になる)。

## 5. HPB掲載終了(掲載エラー)を「活動0件」と混同しない

店舗ページが掲載終了(`https://beauty.hotpepper.jp/kr/slnH000XXXXXX/` にアクセスすると
タイトルが「掲載エラー」になる)の場合、レビュー/ブログ取得関数は例外を出さずに黙って
0件を返してしまう実装だと、「本当に活動が無い月」なのか「もう掲載自体が無い」のか区別が
つかなくなる。`scripts/hpb_review_blog_check.py` の `check_not_delisted()` はこれを検知して
例外を送出し、CSVのerror列に記録する設計にしてある。院マスタに新しいstore_idを登録する際は、
このチェックを経由させること。

## 6. 「掲載エラー」は恒久的な閉店とは限らない — 新しい店舗IDへの移行を疑う

2026-09-07に「掲載エラー」と判定した4院のうち3院(池袋駅前整体院・新松戸クラシオン整体院・
クラシオン整体院MEGAドン・キホーテ長野高田)は、実際には**廃業しておらず、新しい店舗ID
(storeId)で再掲載されていた**ことが2026-09-08に判明した(利用者から正しいURLの提供を
受けて発覚)。旧IDのページが「掲載エラー」を返しても、店名で再検索せずに「閉店した」と
即断しないこと。

**対策:** 「掲載エラー」を確認したら、必ずHPBのジャンル検索(`https://beauty.hotpepper.jp/genre/{ジャンルコード}/{エリアコード}/`。
ジャンルコードの例: `kgkw501`=鍼灸、`kgkw504`=接骨院・整骨院、`kgkw011`=整体・矯正。
エリアコードは対象院の最寄り駅の`stc`コードで、他の同チェーン店のページの「近隣サロン」
リンクや、駅名+ジャンル名で `WebSearch` すれば見つかる)で同じ院名を検索し、新しいIDの
ページが無いか確認してから「未収録」または「掲載終了」と結論づけること。実際に見つかった
新IDの例(2026-09-08時点): 池袋駅前整体院 → `H000742962`、新松戸クラシオン整体院 →
`H000767230`、クラシオン整体院MEGAドン・キホーテ長野高田 → `H000684008`。全て実測値が
手動集計値と完全一致することを確認済み。

## 7. 「あはき」系(鍼灸整骨院/鍼灸接骨院)は独立した別ジャンルで検索する

「◯◯鍼灸整骨院」「◯◯鍼灸接骨院」のように、同じ拠点の「整骨院/整体院」版とは別に
あはき(あん摩マッサージ指圧師・はり師・きゅう師)資格保持者向けの**別ブランドとして
新規登録されているケース**が5院確認された(2026-09-08、上記4の重複バグの当事者と同じ
5院)。これらはHPBの通常の「接骨院・整骨院」ジャンル(`kgkw504`)ではなく「鍼灸」ジャンル
(`kgkw501`)で駅名×鍼灸のジャンル検索をかけると見つかりやすい。store_idの採番も同時期に
まとめて行われたとみられ連番に近い(例: `H000822239`, `H000822241`, `H000822243`,
`H000822244`, `H000822247` — ライフガーデン茂原鍼灸整骨院・本八幡南口鍼灸接骨院・
新潟関屋鍼灸整骨院・新静岡駅前鍼灸接骨院・八幡宿駅西口鍼灸接骨院)。ただし連番だからと
いって未確認のIDに順に当たりを付けるのは非効率(欠番・無関係な店舗も多い)なので、
基本はジャンル検索を使うこと。
