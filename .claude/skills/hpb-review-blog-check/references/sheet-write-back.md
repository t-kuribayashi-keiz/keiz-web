# スプレッドシートへの書き込み手順(ブラウザ経由・暫定運用)

**2026-09-09以降、`--mode apply`(サービスアカウント経由)がGitHub Actionsで本番稼働しており、
通常はこの手順を使う必要はない。** 以下はサービスアカウントが使えない環境(鍵が無いローカル
環境など)向けの代替手順として残してある。書き込み先スプレッドシートは2026-09-11に
「HPB口コミ・ブログチェック」(ID: `12gx_guSdsVToNn3fjA5fzujqrk7E4crs9UE6V9rJ71Y`)に切り替わり、
書き込み対象列もG〜IからB〜Fに変わった(下記の例・URLは切り替え前の旧シートのままなので、
実際に使う際はシートIDと列レター(G〜I→B〜F)を読み替えること)。

サービスアカウントによる `--mode apply` が未検証の間は、`claude-in-chrome`(利用者の実
ブラウザ、ログイン済み)でスプレッドシートを直接編集する。**この手順を飛ばして
いきなり範囲貼り付けをすると、2026-09-07に実際に起きたように既存データを誤った
位置に上書きする。** 必ず以下の順で行うこと。

## 前提: なぜ行番号がズレて見えることがあるのか(訂正版)

2026-09-07時点では「Name Boxのセル移動が実際の書き込み位置より2行下にずれる
Google Sheets側のバグ」だと考えていたが、**これは誤診断だった。** 2026-09-08、
実際にライブのスプレッドシートを直接スクリーンショットで確認したところ、
Name Box(`form_input` + `Return`)によるセル移動は指定どおり正確に動作していることが
判明した。

**本当の原因: Google Drive連携の `read_file_content` はスプレッドシートをMarkdown
テーブルとして返すため、実際のシートには存在しない「区切り行」が2行分、出力の先頭に
挿入される。** 具体的には、`read_file_content` の出力は

```
line1: |  |  |  |  |  |  ...          ← 実際のシートには無い、空の1行目
line2: | :-: | :-: | ...              ← Markdownテーブルの区切り記法。実際のシートには無い
line3: | リクルート原さんご担当 | ... ← ここが実際のシート「行1」
line4: | (写真有りだけ数える) | ...   ← 実際のシート「行2」
line5: | わかば整骨院 | ...           ← 実際のシート「行3」
```

という構造になっており、**「Markdown出力のN行目」は「実際のシートのN-2行目」に対応する。**
2026-09-07に「Name Boxで指定した行より2行下にデータが入った」ように見えた現象は、
「わかば整骨院はMarkdown出力の5行目にあるから実シートの行5だろう」という誤った前提で
Name Boxに「G5」等と入力していたために起きていた。Name Box自体は正しく実シート行5
(実際には佐倉志津整骨院の行)に移動しており、バグはどこにも無かった。

**教訓: `read_file_content` の出力から行番号を取得してセル参照(Name Box、A1記法など)に
使う場合は、必ず2を引いた値を使うこと。** `download_file_content` でXLSXとしてダウンロードし
`openpyxl` で読む場合はこのズレは発生しない(実際の行番号がそのまま得られる)。行番号を
Name Boxでの書き込みに使う予定があるなら、最初から `download_file_content` 経由で
実際の行番号を取得する方が安全。

## 手順

### 1. 対象タブを開く

URLの `#gid=` を対象月のタブのgidに変える(例: `2608月分` タブなら
`https://docs.google.com/spreadsheets/d/1cmYMBJb5do2MsdO43-RS2uD22vEbNJHoPYMZ3hvqEvA/edit?gid=1137011202`)。
gidが分からない場合は、対象タブをクリックしてから `window.location.href` を
`javascript_tool` で確認する。

### 2. 書き込み前に必ず1セルでキャリブレーションする

行番号の取得元(`read_file_content`のMarkdown出力か、`download_file_content`のXLSXか)に
関わらず、本番データを流し込む前に必ず1セルでの確認を行うこと:

1. `find` で「name box」を検索し、`textbox` の子要素(親のgenericではない方)のrefを取得する
2. `form_input` でそのrefに書き込み予定セル(例: 対象範囲の左上セル)を設定する
3. `computer` の `key` で `Return` を1回押す
4. `computer` の `zoom` または `screenshot` で、Name Boxの表示と対象行の内容(列A、
   隣接するB〜F列の既存データ)を直接目視確認し、**意図した院名の行であることを確認する**
   (2026-09-08以降はこれで十分。read_file_contentの再取得は必須ではない — Markdown変換の
   行ズレを再び踏むリスクがあるため、視覚的な直接確認の方が確実)

一致しなければ、行番号の計算(特にMarkdown出力から取得した場合は-2しているか)を
見直すこと。

### 3. クリップボード経由で範囲貼り付け

1. `form_input` でName Boxに実際の行番号の範囲(例: `G24:I28`)を設定し、`Return` を押す
2. `javascript_tool` で `navigator.clipboard.writeText(tsv)` を実行し、タブ区切り・
   改行区切りのブロックをクリップボードに書き込む(行数・列数が選択範囲と一致すること
   を事前に確認する)
3. `computer` の `key` で `ctrl+v` を押して貼り付ける

### 4. 必ず結果を検証する

`computer` の `screenshot` で書き込んだ範囲を直接確認する(Google Sheetsのステータス
バーに表示される「合計:」の値を、貼り付け前に計算した期待値と突き合わせるのが簡単で
確実)。読み取り直しに `read_file_content` を使う場合は、上記のMarkdown行ズレ(-2)を
必ず踏まえて行番号を解釈すること。

一致しなければ、該当範囲を選択して `Delete` キーでクリアしてからやり直す。
中途半端な状態のまま次の範囲貼り付けに進まないこと。

## 今後の展望

`--mode apply`(`GCP_KPI_WRITER_KEY` によるサービスアカウント認証、`hpb_slot_check.py`
と同じ方式)が使えるようになれば、この手順は丸ごと不要になる(gspreadのAPIは実際の
行番号をそのまま扱うため、このMarkdown変換の問題自体が発生しない)。SKILL.mdの
「今後: 完全自動化への道」を参照し、サービスアカウント共有の了承が得られ次第
移行すること。
