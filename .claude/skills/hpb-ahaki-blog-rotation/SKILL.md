# HPB あはき柔整ブログ ローテーション投稿

5院(ライトプラン・あはき柔整プラン並行運用店)の、あはき柔整側HPB店舗ページのブログタブは
「0か1」で放置されがち、という課題(`data/proposals/2026-09-10_あはき柔整プランページブラッシュアップ.md`
参照)に対応するためのSkill。郡山若葉町鍼灸接骨院(あはき柔整へ完全切り替え済みで活発にブログ
運用している店)の投稿を精査して作った、鍼灸のみの店舗でも使い回せる本文テンプレート8種を、
店舗ごとの署名(店名・営業時間・住所・TEL・HP)に自動で差し替えて回す。

**このSkillは`hpb-salonboard-update`を前提にする。** ログイン・反映確認・複数店舗切り替え等の
基本ルールはすべてそちらに従うこと(以下は本Skill固有の追加事項のみ)。

## データの由来と、なぜ8パターンしか無いか

- 出典: `data/proposals/2026-09-12_郡山若葉町ブログ流用候補.md`(郡山若葉町鍼灸接骨院の
  公開ブログ67件を全件精査したもの)
- 67件のうち「含める31件」からさらに、栗林さんの指摘(2026-09-12)を受けて再点検した結果、
  技術名の名指しはなくても「骨盤の歪み」「産後の骨盤の開き」「むちうち」等、柔整/整体領域の
  対応症状を暗示する定型ブロックが付随する投稿(「要確認」8件)は**あえて採用していない**。
  鍼灸のみの店舗で使うと、提供していない施術を暗示する誤表示になるため。
- 残った31件は文章としては8パターンに収束する(同一文章の使い回し投稿が大半)ため、
  `data/blog-templates.json`には重複を除いた8件だけを収録している。
- 元投稿のハッシュタグ欄(「#整体#骨盤矯正#…」)は柔整系タグが混在しているため一切使わず、
  `hashtag_pool`(鍼灸・美容鍼・はり灸・自律神経ケア・血流改善)+店舗の`area_keyword`から
  都度生成する。

## 使い方

### 1. 次の投稿案を機械的に組み立てる(ドライラン、状態は変更されない)

```bash
cd .claude/skills/hpb-ahaki-blog-rotation
python scripts/build_ahaki_blog_post.py next "本八幡南口鍼灸接骨院"
```

店舗名は`data/store-info.json`に登録された5院の名称と完全一致させる(`list-stores`で確認可)。
出力されるJSONには、店舗の署名(自己紹介・営業時間・住所・TEL・HP)まで差し込み済みの
本文全文、カテゴリ、画像パス、生成ハッシュタグ、`banned_word_check`(整体/骨盤矯正/マッサージ等の
禁止語が本文に紛れ込んでいないかの機械チェック)が入っている。

**このJSONをそのまま投稿しない。** 必ず人(栗林さん、またはこのセッションの操作者)が本文と
店舗情報を目視確認してから次のステップに進むこと — SalonBoardへの投稿は公開コンテンツの
公開行為であり、`hpb-salonboard-update`の非交渉ルール2(反映/公開の前には毎回あらためて
明示的な承認を取る)がそのまま適用される。バッチの最初に1回承認を取ったからといって、
5店舗分をまとめて自動で投稿してよいわけではない — **1店舗投稿するごとに次の店舗の前で
一度立ち止まる。**

### 2. 実際にSalonBoardへ投稿する(claude-in-chrome、要ユーザーのログイン済みChrome)

`hpb-salonboard-update`の手順に従う: `mcp__claude-in-chrome__*`ツールをロードし、
ユーザーの実Chromeで`salonboard.com`にログイン済みであることを確認し、
`CNC/groupTop/`から対象店舗(あはき柔整側、上記のstore_nameそのもの。ライトプラン側の
同名に似た店舗と間違えないこと — フッターの店舗名で必ず確認)を開き、`KLP/blog/blogList`
へ進む。

**ブログ投稿画面のクリック手順は2026-09-12時点で未検証。** 新規投稿ボタンの位置、
タイトル/本文/カテゴリの入力欄、画像アップロードの流れ、文字数制限、そして「投稿する」が
即時公開なのか下書き→反映の2段階なのか、いずれも実際に触ってみないと分からない。
**最初の1店舗は探索作業として扱う**: 各ステップでスクリーンショットを取りながら慎重に進め、
分かったことを`../hpb-salonboard-update/references/blog-posting.md`に
(`coupon-editing.md`と同じ形式で)新規に書き残すこと。次の店舗以降はその参照ファイルに従えば
速くなる。

画像は`next`コマンドが返す`image_path`(例: `data/proposals/2026-09-12_koriyama-blog-images/bidA123970283.jpg`、
リポジトリルートからの相対パス)をアップロードする。

### 3. 投稿が確認できたら記録する

```bash
python scripts/build_ahaki_blog_post.py mark-posted "本八幡南口鍼灸接骨院" t01_capillary --url "https://beauty.hotpepper.jp/kr/slnH000822241/blog/xxxxx.html"
```

**投稿の成功を実際に確認できてから記録すること。** 失敗した/公開を見送った投稿を記録すると
次回の店舗別ローテーションが狂う。`--url`は任意だが、後から見返せるので分かる場合は付ける。

## ローテーションの考え方

- 店舗ごとに、まだ使っていないテンプレートを優先。8件すべて使い切ったら、その店舗で
  最も古く使ったものから再び回す。
- 全店舗共通で、直近3日以内に**他の店**で使われたテンプレートはできるだけ避ける
  (5院が同じタイミングで同じ文章を出すと不自然なため)。
- 判断材料はすべて`data/rotation-state.json`(投稿履歴)。**このファイルは
  `mark-posted`経由でのみ更新する — 手で編集しない。**

## 店舗情報が変わったとき

`data/store-info.json`の住所・電話・営業時間は`data/clinics.json`のライトプラン側エントリ
(同一物件なので住所等は共通)から2026-09-12時点で転記したもの。`data/clinics.json`が
更新されたら、この配列も合わせて更新すること。Instagramは各院とも未確認のため`null`
(見つかれば追記し、署名に自動で1行追加される)。

## テンプレートを増やしたいとき

`data/blog-templates.json`に新しいテンプレートを追記する際は、必ず以下を確認してから追加する:
1. 本文が`banned_words`(整体・骨盤矯正・マッサージ・柔整・矯正・もみほぐし・ドライヘッド・
   筋膜リリース・骨格矯正・筋膜ストレッチ)のいずれかの技術をメニューとして名指し推奨して
   いないか(`next`コマンドの`banned_word_check`で機械チェックはできるが、文脈判断が要るので
   最終判断は人が行う)
2. 店名・住所等の店舗固有情報は`{{STORE_NAME}}` / `{{FACILITY}}`のプレースホルダーに
   置き換えてあるか(手書きの店名が本文に残っていないか)
3. 数字の実績主張(「20種類のメニュー」等)が店舗ごとに食い違わないか
