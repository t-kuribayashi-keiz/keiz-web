# クーポン掲載情報の反映申請: 「要確認」1件だけでは全体反映はブロックされない/似た店名の衝突に注意

対象: ライフガーデン茂原鍼灸整骨院(H000822239)・新潟関屋鍼灸整骨院(H000822243)・
新静岡駅前鍼灸接骨院(H000822244)・八幡宿駅西口鍼灸接骨院(H000822247)、いずれも
あはき柔整プランのクーポン掲載情報反映申請(2026-09-18実施)。

## 1. 「要確認」は反映申請ボタンを無効化しない(NGとは別扱い)

`CNK/reflect/reflectTop/`の「反映状況とプレビュー」テーブルの上部に
「※ 掲載チェックにNGがある場合、または「未確認の掲載情報」がある場合、「反映申請」
ボタンを押せません。」という注記がある。これを読むと、掲載チェックが「要確認」の
コースが1件でもあると反映申請ボタン自体が押せなくなるように誤読しやすい。

実機確認の結果、**「要確認」(=画像未設定などで完全ではないが致命的ではない状態)は
このブロックの対象ではなく、実際にブロックされるのは「NG」判定の場合のみ**と判断できる。
根拠:
- 4店舗とも11件中10件「OK」、1件(No.10、口コミ投稿クーポン、画像未設定)が「要確認」
  という同一状態だったが、`document.getElementById('reflectedButtonCpn')`の
  `disabled`属性は常に`false`、CSSクラスも`common-CNKcommon__primaryBtn`(通常の
  有効ボタン)のままだった
- 実際にクリックすると、4店舗すべてで「クーポン掲載情報の本番反映を予約しました。」
  というメッセージが表示され、`reflectTop`の該当行のステータスが「未申請」→
  「反映待ち」に遷移した(エラーも警告ダイアログも出なかった)

したがって、**「要確認」状態のコースが1件だけ残っていても、他が全てOKであれば
セクション全体の反映申請は通る**。ただし今回はNG判定のケースを検証していないので、
「NGなら本当にブロックされるか」は別途要検証(注記の文言通りだと信じてよいが未確認)。

## 2. 似た名前の姉妹店に誤って入ってしまうリスク(部分一致クリックは危険)

`CNC/groupTop/`のサロン一覧で「ライフガーデン茂原」を`textContent.includes()`で
部分一致検索したところ、意図した対象「ライフガーデン茂原**鍼灸**整骨院」(H000822239)
より先に「ライフガーデン茂原整骨院」(H000528120、**鍼灸が付かない別の既存店舗**)が
ヒットし、そちらに入ってしまった。footer確認(`◯◯様 / H0008xxxxx / ...`)で
IDの不一致にすぐ気づいて訂正できたが、もし確認を怠っていれば無関係の店舗の
クーポンを反映してしまうところだった。

**対策**: サロン一覧からのリンク特定は店名の部分一致ではなく、`CNC/groupTop/`の
テーブル上でIDセル(`H0008xxxxx`)を`textContent.trim() === 'H0008xxxxx'`の完全一致で
検索し、その`closest('tr')`内の`<a>`をクリックする方式に統一するべき
(`.claude/skills/hpb-salonboard-update/SKILL.md`本体で既に案内されている
「javascript_toolでDOM要素へ直接click()」の手順に、IDセル起点での行特定も追記候補)。
店舗入場後は必ずfooterの`様 / H0008xxxxx /`をJSで抽出して意図したIDと突合してから
作業を進めること(今回はこれで実際に事故を防げた)。

## 3. Auto Modeブロックは権限モード起因であり、SalonBoard側の問題ではない

前回セッション(2026-09-18午前)ではAuto Mode下で`CNK/reflect/reflectTop`への
`navigate`が「[Production Deploy]」という理由でことごとくブロックされ、
八幡宿駅西口に至ってはサロン切替のクリックすら「[Real-World Transactions]」で
ブロックされていた。今回、呼び出し元セッションがManual/bypassPermissionsモードに
切り替えたところ、同じ操作(サロン切替・反映申請とも)が何の問題もなく通った。
これは`salonboard-publish-auto-mode-block.md`(栗林さんのmemory)に記録済みの
既知の制約の追加実例。**Auto Mode下でSalonBoardの反映系操作(場合によっては
サロン切替すら)がブロックされることがある**ため、反映作業を依頼する際は
事前にManual/bypassPermissionsへの切替を呼び出し元に確認してもらうのが確実。
