# ブログ (KLP/blog/blogList) 投稿手順

2026-09-12、本八幡南口鍼灸接骨院(H000822241)への試験投稿で確認。`hpb-ahaki-blog-rotation`
スキルが組み立てた本文を使い、実際に1件登録するところまで検証済み。

## 一覧画面 (`KLP/blog/blogList/`)

- 「ブログは『掲載管理TOP』画面から『掲載変更を反映する』を押さなくても、ブログ投稿完了
  するとそのまま反映されます。」という案内が出る。**クーポンのような「登録→反映」の
  2段階ではなく、ブログ単体で公開まで完結する**という意味。ただし下記の通り、実際には
  バックエンドの同期待ちが挟まる(「反映待ち」ステータス)。
- 新規投稿ボタンは「新規登録」(左上、青ボタン)。
- 投稿者は「投稿者追加・編集」で最大5名まで、スタッフ登録なしにブログ専用の投稿者名を
  追加できる。既存投稿は概ね「スタッフ 一同」を使っている(郡山若葉町の実例と同じ)。

## 入力画面 (`KLP/blog/blog/`)

フィールドと上限:
- **投稿者**: セレクトボックス(例: `女性 鍼灸師` `スタッフ 一同`)
- **カテゴリ**: セレクトボックス。選択肢は `プライベート` `サロンのNEWS` `おすすめメニュー`
  `おすすめデザイン` `ビューティー` — `data/blog-templates.json`の`category`フィールドと
  そのまま対応する
- **タイトル**: 全角25文字以下
- **本文**: リッチテキスト編集領域(1個のボックスに文章と画像がインラインで混在する)。
  全角1000文字以下、改行80回以下、画像4枚以下。文字カウンタは`computer`の`type`アクション
  (実際のキー入力)でないと更新されない — `form_input`でテキストボックス(タイトル欄)に
  値をセットしてもカウンタ表示は`0/25`のまま止まって見えるが、実際の値は正しく入っている
  (次の画面の確認で反映されているのを確認済み)。本文欄は`generic`要素として`read_page`に
  現れ、通常の`textbox`としては拾えないので、クリックしてフォーカスしてから`type`する
- **クーポン**: 任意(「クーポン選択」ボタン)。付けなくても投稿できる
- **予約投稿**: 「設定しない」(即時)か「設定する」+日時指定

### 画像アップロードの手順(要注意)

1. まず「画像アップロード」ボタンをクリックしてモーダルを開く(クリック前に
   `file_upload`ツールで隠れた`<input type=file>`にファイルを流し込んでも、モーダルの
   UIには反映されず`登録する`ボタンはグレーのまま――**モーダルを開く前のアップロードは
   効かない**)
2. モーダルが開いた状態で、`find`等で見つけたその同じ`<input type=file>`の ref に対して
   もう一度`file_upload`を実行する。今度はプレビュー画像が表示され、モーダル内の
   「登録する」ボタンが有効になる
3. モーダル内の「登録する」をクリックすると、本文の編集領域の先頭(カーソル位置)に
   画像がインライン挿入される。画像は本文エリアの外の独立した欄ではなく、本文と同じ
   ボックスに埋め込まれる
4. 画像の後ろをクリックしてカーソルを移動し、そこから本文テキストを`type`する

### 確認画面 (`KLP/blog/blog/confirm`)

- 入力内容がそのまま表示される(タイトル・カテゴリ・投稿者・画像・本文全文)
- **ボタンが2つある**: 「登録・反映する」(即座に公開) と「**登録・未反映にする**」
  (下書き保存、公開しない)。後者を使えば、SalonBoard側にブログを保存だけして実際の
  公開は後回しにできる ―― この画面に来て初めて分かった選択肢で、一覧画面の案内文
  (「反映するボタンを押す必要はない」)だけを読むと分からない。**下書きのまま置いておき
  たい場合はこちらを使う**
- 「登録・反映する」を押すと`KLP/blog/blog/complete`(完了画面)に遷移し、
  「ブログの登録が完了しました。」と表示される。「ブログの内容によってはリクルート側の
  判断により非掲載とさせていただくことがございます」という注記もある(内容次第で後から
  拒否されうる、ということ)

## 公開までのタイムラグ(重要な発見)

一覧画面の案内文とは裏腹に、「登録・反映する」を押した直後にブログ一覧のステータス欄を
見ると **「- 反映待ち」** と表示され、投稿から30〜40秒待っても変わらなかった。同時に
`beauty.hotpepper.jp`側の公開ページ(`https://beauty.hotpepper.jp/kr/sln<店舗ID>/blog/`)
を見ても、その間は「ブログが掲載されていません。」のままだった。

**つまり「投稿完了=即座に公開」ではなく、バックエンド側の反映バッチ(所要時間不明、
数分〜それ以上の可能性)を待つ必要がある。** 一覧画面のステータスが「反映待ち」から
掲載中を示す表示に変わったこと、または公開ページに実際に表示されたことを見てから
初めて「公開された」と判断すること。反映待ちのまま長時間(例: 数時間)変わらない場合は
異常の可能性があるので、その時点で栗林さんに報告し、次の店舗の投稿を続けるかどうか
判断を仰ぐこと。

## 画像アップロードモーダルの再現性(2026-09-12、5院展開時に確認)

「画像アップロード」ボタンを押してモーダルを開いた直後に`file_upload`しても、その場では
プレビューが出ず「登録する」ボタンがグレーのままのことがある(店舗によって発生したりしなかったり、
再現条件は不明)。その場合は同じ`<input type=file>`の ref に対して**もう一度**`file_upload`を
実行すれば、プレビューが表示され「登録する」が有効になる。1回で決まらなくても慌てず、
同じrefにもう一度投げれば直る。

## タイトル・本文の転記精度を必ず機械的に検証する(重要、2026-09-12に実際に事故があった)

5院展開の2店舗目で、タイトルの1文字(「浮腫み」→「浮腍み」)が化けて登録されかけた事故が
あった。原因はモデル(Claude)がJSON出力を見て**手で文字を再入力**したこと ―
日本語の類似字形(腫/腍等)を目視でコピーすると取り違えるリスクがある。対策:

1. **タイトルは`computer`の`type`で打たず、JSで直接セットする**。
   `document.querySelector('input[type=text]')`に対して
   `Object.getOwnPropertyDescriptor(window.HTMLInputElement.prototype,'value').set`経由で
   値を設定し、`input`/`change`イベントをdispatchする。そのうえで**必ず直後に
   `Array.from(el.value).map(c=>c.codePointAt(0).toString(16))`でコードポイント列を取得し、
   スクリプトが出力した元のタイトル文字列のコードポイント列(Pythonで`hex(ord(c))`を回せば
   出せる)と突き合わせる**。見た目でなく符号点で比較することで、目視では区別しづらい
   文字化けも確実に検出できる
2. **本文は`computer`の`type`で入力してよい**(長文なので手打ちJSでの再現は非現実的)が、
   入力後に**空白・改行を除去した正規化テキストのSHA-256ハッシュ**を、期待値(スクリプト
   出力の`body`を同様に正規化してハッシュ化したもの)と突き合わせて確認する。生の
   `innerText`は本文中の空行(`\n\n`)がcontenteditable側で1個の改行に潰れることがあるため、
   ハッシュ比較の前に**両者とも空白類を除去してから**比較しないと、内容が同一でも
   ハッシュが一致せず誤検知する
3. どちらの検証も「確認する」を押す前、まだ入力画面にいる段階で行うこと。確認画面の
   `get_page_text`で目視確認するのは最終チェックとして有効だが、上記の機械検証の代わりには
   ならない(1文字の字形違いは目視では見逃しうる)

## 「確認する」「登録・反映する」ボタンのref クリックが効かないことがある

`find`で見つけた ref に対して`computer`の`left_click`を撃っても、ページ遷移が起きず
同じ画面に留まることが複数回あった(5院展開のうち少なくとも2回)。原因は不明(本文が長くて
ページが伸び、ボタンの実座標とref解決時の座標がズレた可能性)。**遷移したはずのURLを
`get_page_text`で確認し、変わっていなければ、素直にスクリーンショットを撮って実際に見えている
座標へ`left_click`する**とほぼ確実に成功する。ref クリックを過信せず、遷移確認→ダメなら
座標クリック、の順で対応すること。

## 複数店舗への展開時の注意

- 店舗切り替えは`hpb-salonboard-update`本体の「`javascript_tool`で`<a>`を
  `element.click()`する」手法をそのまま使う(座標/ref クリックが数店舗目で失敗する
  既知の問題があるため)
- あはき柔整プラン側の店舗名(例: `本八幡南口鍼灸接骨院`)と、同じ地域名を含む
  ライトプラン側の店舗名(例: `本八幡南口整体院`)は`CNC/groupTop/`の一覧で並んでいることが
  あるので、クリック前にどちらの名前か再確認すること。フッターの店舗名(`<店舗名>様 /
  <店舗ID> / ...`)で必ず照合する
