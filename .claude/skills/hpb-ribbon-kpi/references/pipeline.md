# 抽出ロジックの内部(リボンPDFのどこから何を取るか)

`scripts/hpb_ribbon_extract.py` の詳細。純粋関数はテキストのfixtureで
`tests/test_hpb_ribbon_extract.py` が固めている。

## PDFの構成(1店舗23〜25ページ)

| ページ | 内容 | 使う値 |
|---|---|---|
| P1 予約数推移 | 予約数・性別・年齢の14か月時系列、マイページ登録数 | 女性率 / 20代未満〜50代以上比率 |
| P3 掲載状況 | 自サロン名・比較サロン | 院名(「最寄駅」の直後の行) |
| サマリ(P4付近) | 自サロンTOP PV / CVR / ACR の 自社・エリア平均・比較 | PV/CVR/ACR と 予約数(前月/新規) |
| P5/P14/P17 | PV推移 / CVR推移 / ACR推移(時系列) | 検算用(サマリと一致するはず) |

サマリページは `自サロンTOP PV` と `自サロンCVR` の両方を含むページを探して特定する
(ページ番号は店舗により23/25ページで前後する)。

## 完了月の決め方

- **サマリページ**の3値は"最新の完了月"のスナップショット。ページ番号や列位置に依存せず、
  ラベル直後の3数値=自社/エリア平均/比較。
- **時系列(P1)**は末尾が『当月号(進行中)』『翌月号』。完了月は**末尾から2列目**(`-2`)。
  行はラベル行の直後の連続する数値/ダッシュ行として読む。`- %`(空データ月)は
  **値Noneだが列としては数える**。これをしないと開店直後の店舗で列がずれる。

## 値の対応(サマリ→Master)

```
自サロンTOP PV        → 自社PV(1つ目) / エリア平均PV(2つ目)   ※3つ目は比較サロン=使わない
自サロンCVR           → 自社CVR / エリア平均CVR
自サロンACR           → 自社ACR / エリア平均ACR
前月予約数            → 集客数_ribbon_ALL(参考。Masterの集客数には使わない)
新規予約 / リピート予約 → 新規予約数実績(新規側)
```

Masterの「集客数」は**リボンではなく集客数シート**の当月値を使う(社内の集客数定義)。
リボンのALL予約(前月予約数)はCSVに `集客数_ribbon_ALL` として残すが、Masterには入れない。

## 健全性チェック(validate_row)

- PV/CVR/ACR/エリア平均/新規/女性率の欠損
- 時系列の列数(概ね14)
- 年代5区分の合計が90〜110%
- PV/CVR/ACRが全欠損なら「空データ(開店直後の可能性)」として1件にまとめる(全「-」の新規店)

2026年8月号(173店)での要確認は、開店直後の空データ3店と、8月予約0で年代0%の1店のみ。
これらは不具合ではない。
