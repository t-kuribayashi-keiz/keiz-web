## 1. 店舗↔プロパティ対応

- 対象は `data/clinics.json` の `brand` が「直営」または「サンズミライ」の店舗、**計153店舗**

  文字列一致させれば、**153店舗中147店舗は自動でマッピングできる**(2026-09-15実施済み、
  `data/genai-search-visibility-properties.json` に反映済み)。
- 残り6店舗(ふじみ野駅西口接骨院/四条烏丸中央整骨院/四街道もねの里接骨院/
  アクロスモール守谷接骨院/姪浜駅南2丁目接骨院/薬園台駅東口接骨院)は、プロパティ検索欄で

## 2. レポートへの到達(URL直接ナビゲートで十分、クリック操作は不要)

以下のURLに直接 `navigate` すれば、プロパティ切替・「検索パフォーマンス→生成AI機能」タブ
クリック・期間指定モーダル操作のすべてを省略できる:

```
https://search.google.com/u/1/search-console/performance/search-analytics/ai?resource_id=<URLエンコードしたプロパティ>&start_date=YYYYMMDD&end_date=YYYYMMDD
```

- `resource_id`: プロパティURL(末尾スラッシュ込み)をURLエンコードしたもの
  (例: `https://genki.chiryouin.biz/` → `https%3A%2F%2Fgenki.chiryouin.biz%2F`)
- `start_date` / `end_date`: `YYYYMMDD`形式(ハイフンなし)。**必ず両方指定すること**
  (省略するとデフォルトの「3か月」表示になり、狙った月と一致しない)。
- 上記URLに `navigate` した直後は反映が遅れることがあるため、2秒程度 `wait` してから
  読み取ること。
- モーダル(「詳細」ボタン→期間ダイアログ)経由でカスタム日付を入力する場合は、日付欄が
  ネイティブの日付ピケットではなく **`YYYY-MM-DD`のテキスト入力**であることに注意
  (`20260801`のような区切りなし入力はエラーになる)。ただし上記URL直接方式のほうが
  クリック数が少なく確実なので、フェーズBでは基本的にURL直接方式を使う。

## 3. 合計表示回数の読み取り

- `get_page_text` を使い、`合計表示回数` という文字列の直後に出てくる数字を読む。
  (画面上には「表示回数」という文字列がグラフ軸ラベルとしても出るため、必ず
  「合計表示回数」という4文字セットの直後の数字を対象にすること)
- 出力例:
  ```
  合計表示回数
  303
  ```
- ページ別内訳(「上位のページ」テーブル)は今回不要(栗林さんの指示: 店舗合計のみで十分)。
- デバイス/国フィルタは既定(未指定=全デバイス・全国)のままでよい。画面のアクセシビリティ
  ツリー上に「国: 米国」「デバイス: PC」といったフィルタ候補のダミー要素が見えることがあるが、
  これは「フィルタを追加」メニューの選択肢候補であり、実際に適用されているフィルタでは
  ない(画面上のフィルタバーに実際のチップが無いことをスクリーンショットで確認済み)。

## 4. 集計期間

- 栗林さんとの合意: **2026年5・6・7・8月を1か月ごとに区切って集計**(店舗ごとに4回読む)。
- `start_date` / `end_date` の組み合わせ:
  - 5月: `20260501` 〜 `20260531`
  - 6月: `20260601` 〜 `20260630`
  - 7月: `20260701` 〜 `20260731`
  - 8月: `20260801` 〜 `20260831`

**重要な注意(2026-09-15フェーズBで判明): 5月だけ実質14日分の合計しかない。**
`start_date=20260501`を指定しても、この生成AI機能(AI Overviews)レポート自体のデータ収集が
Search Console側で始まったのが2026年5月18日頃らしく、実際にグラフに出る日付は
「2026/05/18」からで、ページ本文にも「2026年5月18日～2026年5月31日 の合計表示回数の件数を
含む」と明記される。つまり**5月の「合計表示回数」は5/1〜5/31の31日分ではなく5/18〜5/31の
14日分の合計**であり、6・7・8月(各月まるごと)とは母数が異なる。店舗間比較・月次トレンドの
報告では必ずこの注記を添えること(5月だけ他の月より少なめに出るのは店舗側の問題ではない)。

## 5. 異常系の見分け方

- **正常(データあり)**: 「合計表示回数」の直後に数字が表示される。
- **データなし/未生成**: 「合計表示回数」自体が表示されず、代わりに
  「データを処理しています。1 日後にもう一度ご確認ください」という文言が出る
  (表側テーブルも「データがありません」)。2026-09-15の検証では、生成AI機能データが
  存在しない古い期間(2020年など)を指定した際にこの表示になった。
- **未来日付・データ未生成期間を指定した場合の罠**: エラーにならず、GSCが自動的に
  「データが存在する直近の日」までの範囲にこっそり読み替えて表示する
  (例: 2027年1月を指定したのに実際は2026年9月14日のデータが出た)。
  **読み取ったあと、ページ本文中の「〜の合計表示回数の件数を含む」という文言や、
  グラフのx軸日付が指定した期間と一致しているか必ず確認すること。** 一致しなければ
  その店舗はスキップして「要確認」に回す(黙って誤った数字を採用しない)。
- **アクセス権エラー**: 未検証(admin@keizgroup.jpは今回対象の147プロパティ全てに
  アクセスできたため、権限エラー画面には遭遇していない)。フェーズBで実際に遭遇したら
  画面の文言をそのまま記録し、「要確認」として空欄で次へ進む。

## 6. フェーズBでの効率化についてのメモ

  navigate → 2秒wait → get_page_textで「合計表示回数」を読む」という単純な繰り返し作業になる。
  画面クリックはほぼ不要。
- 147店舗 × 4か月 = 588回の読み取りが必要。1件ずつ`navigate`+`get_page_text`のペアで進める。
