# グッド(グッドフォーチュン、広島県7院)WEB集客状況分析と基盤整備計画

- 作成日: 2026-09-07
- 作成: good-marketing-strategist
- 対象: グッド7院(`data/clinics.json` id: `good-miyauchi`/`good-jike`/`good-saijo`/
  `good-danbara`/`good-fuchu`/`good-gion`/`good-kamezaki`)。除外店舗は現時点で確認されて
  いない(スマイルの「完全除外4院」に相当する区分はグッドには無い)

## 背景/課題

### 今回の分析の前提(重要・正直に明記する)

このセッションはクラウド実行環境(hostname `vm`)で動いており、Sheets API用の鍵ファイル
(`smile-good-reporter.json`・`ad-spend-reporter.json`)はローカルPC(Keizgroup500)にしか
存在しない。加えて、`brands/good/CLAUDE.md`・`docs/org-review-log.md`によれば、集客KPI用
サービスアカウント`smile-good-reporter@keizgroup-automation.iam.gserviceaccount.com`の鍵を
GitHub Actionsシークレット`GCP_SMILE_GOOD_KEY`へ登録する作業が**未了(唯一の残りタスク)**
のままだった。本セッションでもgh CLI経由での確認・ワークフロー起動を試みたが、いずれも
このClaude Codeインスタンスの権限設定でブロックされた(意図的な安全策であり、回避を試みて
いない)。

したがって、**「グッド・スマイル月次報告」(SEO/MEO順位・施策メモ)・「広告費」
(院別広告実額)の2シートの実データを、今回このセッションから直接取得することはできな
かった。** 以下は`brands/good/CLAUDE.md`および`docs/org-review-log.md`に既に記録されている
「過去のセッションが実際に確認した事実」のみを根拠にした分析であり、新たな数値を作り出して
いない。

### 確認できている事実(定量)

1. **HPB(HotPepper Beauty)掲載状況**: 2026-09-02、`salonboard-operator`の初回実運用で
   グッド7院**全院**のクーポン掲載状況を確認済み。段原鍼灸接骨院(`good-danbara`、
   H000657363)のみクーポン未登録だったため、他院と同一内容で新規作成し、ユーザー承認の
   上で反映(公開)済み。**現時点でグッドに「HPB非掲載院」は存在しない**(スマイルにある
   「HPB掲載5院/非掲載6院」の切り分けは、グッドには当てはまらない可能性が高い。ただし
   これは「掲載していることの確認」であり「掲載を継続する方針かどうか」は別問題として
   未確認)。
2. **HPB経由集客数**: 「グッド・スマイル月次報告」の月次タブHPBブロックに、グッド7院
   すべての院別×月次のHPB集客数が入っている。2026年最新月で**グッド合計75件・1院あたり
   平均10.7件**。同じ基準のスマイル(1院あたり平均2.5件)と比べて**約4.3倍**であり、
   グッドはHPB経由の比重が明確に大きいチャネル構成であることが数字で確認できる。
   ただし店舗別の内訳(どの院が牽引しているか)は今回未取得。
3. **HPBの評価系データは全店「-」(空)**: 同じHPBブロックの口コミ評点・口コミ件数・
   比較サロン最高点・予約枠(×の数)は7院すべて空欄。**したがって「どの院の口コミ評価が
   低いか」「競合比較でどの院が劣勢か」は、現状データからは一切判定できない**
   (推測で埋めない)。埋めるには`GCP_SMILE_GOOD_KEY`登録 → `--profile smile-good`での
   HPBリボンデータ運用の本稼働が必要。
4. **広告費データの存在確認のみ**: 「広告費」スプレッドシート(「広告費各詳細」タブ)の
   2026年8月分に、グッド7院分の金額データ行が存在することは確認済み(ただし店舗名
   マッチングの副産物として件数のみ確認されたもので、グッドはこのシートを使ったKPI集計
   自動化の対象ブランドではない)。**実際の金額・Google PPC/meta等の媒体別内訳は
   今回も未取得。**
5. **`data/clinics.json`のグッド7院は`acquisition_channels`が全店空配列のまま。**
6. **祇園鍼灸接骨院(`good-gion`)のメールアドレス不一致**: ローカル部
   `chitoseshinkyuuseikotuin`が院名(祇園)・地名と一致しない。院マスタ由来のまま採用されて
   おり、誤って別院のメールアドレスが記載されている可能性がある。**裏取り未確認**。

### 未確認事項(推測で埋めていない項目)

- SEO/MEOの実際の順位数値、月次施策メモの内容(「グッド・スマイル月次報告」の
  「報告用」「集計用(栗林)」タブに存在する可能性が高いが、鍵未登録のため今回未読み取り)
- Google PPC・meta広告の配信範囲・予算実額(店舗別・媒体別)
- GA4・Google Search Consoleの連携状況(リラックスのようなブランド別サービスアカウント
  構成は、グッドではまだ影も形もない。そもそもグッドが自社サイト
  <chiryouin.biz系>にGA4/GSCタグを入れているかどうか自体が未確認)
- CRM新規来院数データの所在(広告費とのCVR/CPA監査に必須だが、どのシート・システムに
  あるか本セッションでは特定できていない)
- HPB利用継続方針(掲載していることは確認済みだが、費用対効果を踏まえて継続するかは
  経営判断であり未確認)

## 施策案

データが薄いため、今回は「戦略の中身」ではなく**次の分析を可能にする基盤整備**を優先施策
とする。番号は依存関係の順。

### Phase 0(最優先・栗林さんのローカル作業が必須): サービスアカウント鍵の登録

- 対象: `GCP_SMILE_GOOD_KEY`(GitHub Actionsリポジトリシークレット)
- 内容: ローカルPC(Keizgroup500)の`claude\keys\smile-good-reporter.json`の中身を、
  GitHubリポジトリのSecretsへ登録する(鍵の中身はチャットに一切貼らない)
- 完了後にできるようになること: クラウドセッションから`sheets-smoke-test.yml`
  ・`hpb-ribbon-kpi.yml --profile smile-good`をworkflow_dispatchで起動し、
  「グッド・スマイル月次報告」の実データを継続的に読み取れるようになる
- 期限目安: 次回グッド分析セッションの前まで

### Phase 1: 「グッド・スマイル月次報告」からのSEO/MEO実数値の取得

- Phase 0完了後、`sheets-smoke-test.yml`で「報告用」(gid=275192848、グラフの参照元は
  「集計用 (栗林)」側を読むこと。スマイル側での既知の注意点と同じ)・「集計用 (栗林)」
  タブを読み、グッド7院分のSEO/MEOキーワード別順位・月次施策メモを抽出する
- 院ごとに「伸び代のある媒体」を定量的に特定し、次回の本エージェント起動時にこの
  提案書を更新する

### Phase 2: HPBリボンデータ運用の本稼働(評価系データを埋める)

- `functions/hpb-ribbon-kpi/CLAUDE.md`の`--profile smile-good`を、Phase 0完了後に
  `--mode init-master → inspect → dry-run → apply`の順で実行
- これにより口コミ評点・件数・比較サロン最高点が埋まり、初めて「どの院の評価が競合比較で
  劣勢か」「低評価口コミへの返信対応が必要な院はどこか」を定量的に判定できるようになる
  (現状は空欄のため判定不能)

### Phase 3: 広告費実額の取得とCVR監査

- Phase 0完了後、`ad-spend-reporter`用の鍵(ローカルにのみ存在)経由で「広告費各詳細」
  タブのグッド7院ブロックを実際に読み、店舗別・月別の広告実額と媒体内訳を確認する
- CRM新規来院数データの所在をユーザーに確認したうえで、広告費とCRM新規来院数の連動性
  (「アクセスを無駄喰いして成果ゼロ」のザル状態になっていないか)を監査する。
  この監査はスマイルのように「月5万円」等の既知額を前提にせず、実際に取得した金額のみで
  行う

### Phase 4(検討・要ユーザー判断): GA4/GSCブランド別サービスアカウント構成の適用要否

- リラックスで確立した型(`relax-reporter`専用サービスアカウント、GCPプロジェクト
  `keizgroup-automation`、GA4はアカウント単位で閲覧者を1回付与、GSCはプロパティ単位で
  個別付与)は、**グッドがGA4/GSCを導入している前提**でのみ有効
- まずユーザーに「グッドの各院サイト(chiryouin.biz配下)にGA4/GSCのタグが入っているか」
  を確認する。導入済みであれば`good-reporter`のような専用サービスアカウントを新規発行し、
  `scripts/analytics_discover.py --brand グッド --key-env GCP_GOOD_KEY`で疎通確認する
  (リラックスと同じ手順、ブランド名を差し替えるだけ)
- 未導入であれば、GA4/GSC連携よりも先にタグ導入自体が前提作業になる(この場合は
  実装担当と相談が必要な範囲)

### 優先度の低いフォローアップ

- 祇園鍼灸接骨院のメールアドレス不一致の裏取り。実務影響(誤送信リスク)はあるが、集客
  戦略そのものへの影響は小さいため、Phase 0〜3と並行で栗林さんに直接確認すれば足りる

## 期待効果

現時点では実額データが無いため、KPI変化の定量予測は行わない(推測で数字を作らない)。
Phase 0〜3完了後にmeasurerが検証できるようになる指標は以下の通り:

- HPB経由新規来院数(院別・月次)の推移と、口コミ評点・件数との相関
- 広告費(院別・媒体別)に対するCRM新規来院数の比率(実質CPA)
- SEO/MEO順位の推移と、HP経由流入・来院数の連動

## 執筆指示書

**今回は該当なし。** 理由: ブログ・広告文・口コミ返信のいずれも、対象となる実データ
(順位が低いキーワード、返信が必要な低評価口コミ、成果の出ていない広告クリエイティブ等)
が未取得のため、執筆指示書を作成すると根拠のない当てずっぽうの企画になってしまう。
Phase 1(SEO/MEO実数値取得)・Phase 2(口コミデータ取得)の完了後、実データに基づいて
執筆指示書を作成する。
