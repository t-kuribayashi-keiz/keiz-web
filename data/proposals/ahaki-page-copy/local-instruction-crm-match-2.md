# ローカルセッション向け指示: 実来院数を「新規」だけで数え直す

対象: **あはき柔整プラン5院**(本八幡南口・ライフガーデン茂原・新潟関屋・新静岡駅前・八幡宿駅西口)

## なぜやり直すのか(重要)

レポートで8月と9月の実来院数を並べたが、**2つの数字は数え方が違う。**

| | 出どころ | 数えているもの |
|---|---|---|
| **8月** | スプレッドシート「HPB月別予算比較売上」の「8月単月来院数」列 | HPB経由の**新規獲得**来院数 |
| **9月** | 前回の簡易突合 | 突合できた**全予約**(新規+再診) |

8月側が新規ベースであることは、同じファイルの「獲得単価と平均来院数」タブで
`掲載費総額 ÷ 総来院数 = 単価` を計算していることから確認済み
(例: 2024年8月 7,485,000 ÷ 2,622 = ¥2,855)。

**CRMのステータスで新規と再診は分けられる**(栗林さん確認済み)。

- **新規 = 「新患」+「トライアル」**
- 再診 = それ以外

したがって9月側も新規だけで数え直せば、8月と同じ土俵になる。
**今の5.1倍は再診を含んだ上限値**なので、新規だけにすると下がる可能性が高い。

## やること

### 1. CRMの抽出をやり直す(ステータス列を含める)

LiGUA CRM(`web.ligua.jp`)の「分析Web」→「条件検索」で、対象5院・
**来院日 2026/08/01〜2026/09/30** でカルテ一覧をExcel出力する。

前回との違いは2つ:

- **期間を8月1日まで遡る。** 8月を同じ方法で計算し直せば、シートの「8月単月来院数」
  (あはき柔整5院合計7件)と突き合わせて**方法の妥当性を検証できる**。
  近い値が出れば、9月の数字も同じ方法で出したものとして安心して並べられる
- **ステータス(新患/トライアル/再診)の列を必ず含める。** これが今回の主目的。
  列名が違う場合は、画面上でどの列がそれにあたるかを確認して報告すること

**9月が終わってからでないと回せない。** 10月1日に予定している
「CVR・ACRの9月確定値の取得」と同じタイミングでまとめて行う
([local-instruction-report-2.md](local-instruction-report-2.md) 参照)。

### 2. 突合をやり直す

HPB側は前回と同じSalonBoard予約一覧(対象10掲載)。期間を8/1〜9/30に広げる。
突合の判定方法は前回と同じ(電話番号→かな氏名の単純一致)でよい。
キャンセル(お客様/サロン/無断)は前回同様あらかじめ除外する。

### 3. 集計する

**あはき柔整5院について、店舗×区間×新規/再診 で集計する。**

区間:

| 区間 | 日数 |
|---|---|
| 8月単月(8/1-8/31) | 31 |
| 改修前(9/4-9/10) | 7 |
| 第1段階後(9/11-9/17) | 7 |
| 第1+2段階後(9/18-9/23) | 6 |
| 改修後通算(9/11-9/23) | 13 |
| 9月単月(9/1-9/30) | 30 |

各セルで次の3つを出す:

- 突合できた実来院数(全件)
- うち **新規**(新患+トライアル)
- うち **再診**

ライトプラン側も同じ形で出す(カニバリズム検証を前回と同じ条件で続けるため)。
ただし**ライトプラン側は8月シートの数字と並べてはいけない**
(本八幡南口は9/4-10の7日間だけで予約19件=月換算80件超に対し、シートの8月来院数は26件。
定義差が大きすぎる)。

### 4. 検証する(これを飛ばさない)

**8月の新規件数が、シートの「8月単月来院数」(下表)と近いかを確認して報告する。**

| 店舗 | シートの8月来院数 |
|---|---|
| 本八幡南口 | 1 |
| ライフガーデン茂原 | 2 |
| 新潟関屋 | 1 |
| 新静岡駅前 | 3 |
| 八幡宿駅西口 | 0 |
| **5院合計** | **7** |

- **近い値が出た場合**: 9月の新規件数をそのまま8月と並べてよい。その旨を報告に書く
- **大きくずれた場合**: 並べてはいけない。**ずれの方向と大きさ、考えられる原因を報告する**
  (突合の取りこぼし / シート側が別の定義 / トライアルの扱い 等)。
  **勝手にどちらかに寄せて辻褄を合わせないこと**
