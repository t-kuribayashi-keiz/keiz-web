### 1.3 既に確認できている事実(定性・定量を区別)

- **広告費実額データの店舗数不整合(定量的な要確認事項)**: 「広告費」シートではスマイル
  ブランドの行が6院分しか確認できていないが、院マスタは11院。EPARK掲載店舗リスト
  (2026年8月)では「有限会社スマイルストーリー」11件が院マスタと一致しており、院マスタ側が
  正しく広告費シートが一部院のみを扱っている可能性が高いとされているが**確証はまだない**
  (docs/backlog.md)。この不整合が未解消のままだと、Google PPC/Meta広告の「ザル状態」監査
  (CRM新規来院数と広告流入の連動性チェック)を11院フルセットで行えない
- **HPBデータの「受け皿はあるが中身が無い」状態**: 「グッド・スマイル月次報告」のHPBブロックには
  院別×月次のHPB集客数は既に入っているが、口コミ評点・口コミ件数・比較サロン最高点・
  予約枠(×の数)・当月前月低評価口コミの有無は**HPB掲載5院すべてで空欄("-")**
  ([functions/hpb-ribbon-kpi/CLAUDE.md](../../functions/hpb-ribbon-kpi/CLAUDE.md))。
  したがって現時点では、HPB掲載5院について「予約枠の一部閉塞による機会損失」を定量的に
  あぶり出す材料が存在しない(存在しないこと自体が課題であり、推測で埋めていない)
- **他セッションによる並行作業の兆候**: 「報告用」タブの施策メモに「SEO：試験的に、
  クロードコードによる運用開始」との記載があるとの記録が brands/smile/CLAUDE.md にある。
  このセッションからはシートを読めないため詳細未確認。**本格的なSEO施策着手前に、
  栗林さんへ詳細確認を行い重複を避ける必要がある**
- **未確認(推測で埋めない)**: SEO/MEOキーワード別の実際の順位、GA4/GSCのセッション数・
  流入チャネル別数値・CVデータ、CRM新規来院数と広告流入の連動性の実態、Meta広告の
  「勝ちクリエイティブ」の中身、HPB予約枠の実際の閉塞状況、各院の口コミ評点・件数

## 2. 施策案

### 施策A(最優先・基盤整備): クラウド実行環境からもスマイルの実データを読める状態にする

対象: 分析基盤全体。担当: 栗林さん(ローカルPC作業)+ 次回のローカルセッション。

1. `GCP_SMILE_GOOD_KEY` をGitHub Actions Secretsに登録する(鍵ファイルは
   `claude\keys\smile-good-reporter.json`)。登録済みになれば、`hpb-ribbon-kpi.yml`
   `--profile smile-good` をActions経由(=クラウド環境からも)で回せるようになる
2. 専用Master「HPB_スマイル・グッド_KPI一括集計結果」に対し `--mode init-master` を1回実行
   (1が終わり次第)。実行後、`inspect → calibrate → dry-run → apply` の順で「グッド・
   スマイル月次報告」の集客数と突き合わせ、HPB掲載5院の集客数を継続的に追える状態にする
3. 「広告費」シート用のサービスアカウント鍵(`ad-spend-reporter.json`)についても、
   同様にGitHub Secretへ登録することを検討する(現状Secret名自体が未定義)。登録後、
   「広告費各詳細」タブからスマイル11院分の実額を取得し、1.3で指摘した6院/11院の
   不整合を解消する
4. 3で取得した実額データを使い、Google PPC(11院・月5万円)・Meta広告(2院・月5万円)の
   「アクセス無駄喰い」監査を、CRM新規来院数との突き合わせで初めて定量的に実施できるように
   する(このステップ自体は次回セッション以降の作業)

期限目安: 1〜3は次回、栗林さんがローカルPC(Keizgroup500)から着手できるタイミングで
1〜2週間以内。

### 施策B(基盤整備・要判断): GA4/Search Console 直接APIアクセスの新設要否

現状スマイルは「グッド・スマイル月次報告」という人手集計シート(SEO/MEO順位の要約値+
施策メモ)の読み取りのみが計画されており、姉妹ブランドのリラックスのように各院サイトの
GA4データAPI・Search Console APIへ直接アクセスする経路はまだ設定されていない。

- スマイル11院の自社サイトは `https://chiryouin.biz/<院slug>/` という**単一ドメイン配下の
  パス構造**([data/clinics.json](../../data/clinics.json) の各院`website`列で確認)。
  リラックスでは「1ドメインでもGA4プロパティは店舗ごとに別だった」という実例
  ([brands/relax/CLAUDE.md](../../brands/relax/CLAUDE.md))があり、スマイルでも同じ罠が
  再現する可能性がある。GA4アクセスを新設する場合、店舗ごとのプロパティ有無をAdmin API
  `accountSummaries` で確認する工程が要る
- 似た `chiryou-in.biz`(ハイフンあり)ドメインをサンズミライが使っており、混同しないよう
  注意(スマイルは `chiryouin.biz`、ハイフンなし)
- 判断が必要な点: 人手集計シート(要約値+施策メモ)で当面足りるとするか、リラックスと
  同水準の生データ(クエリ別掲載順位、チャネル別セッション、CV)まで踏み込むかは、
  栗林さんの判断を仰ぎたい。後者を選ぶ場合、GA4はアカウント単位で1回、GSCはプロパティ
  ごとに個別で権限付与が必要(リラックスと同じ手順)

### 施策C(データ非依存・即着手可能): HPB非掲載6院の自社HP SEOメタデータ整備

HPBに掲載していない6院(おおとり・金剛・岸和田・泉が丘・春木・きたのだ)は「自社HP・
MEO一本化戦略」の対象であり、実データの整備を待たずに着手できる。院マスタに既にある
確定ファクト(住所・エリア・電話・診療時間・定休日)と、ブランド共通の強み
(ママ層配慮、骨盤矯正の安全性、交通事故対応)を使い、既存の各院トップページの
title/descriptionを、`smile-marketing-strategist`のSEOルール(title32文字以内・
最重要キーワードを先頭15文字以内・description120文字以内・院固有ファクトを30%以上)に
沿って再設計する。詳細は本紙末尾の「執筆指示書」を参照。

期限目安: 指示書ベースでcontent-writerへ渡し、2週間以内に6院分の初稿を得る。

### 施策D(保留): Meta広告の他院横展開検討

岸和田院・きたのだ院の2院で走っているMeta広告について、「勝ちクリエイティブ」の実データ
(CTR・CVR等)が未取得のため、他院への横展開提案は時期尚早と判断する。施策Aで広告費実額と
クリエイティブ単位のパフォーマンスデータにアクセスできるようになってから、改めて着手する。

- title: 32文字以内。最重要キーワード「[エリア名]+ 整骨院/接骨院/肩こり・腰痛」を必ず
  先頭15文字以内に配置。院名(正式名称)は末尾でよい
